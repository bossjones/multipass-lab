Act 1/The Setup 04 / 26
The premise

Why one agent wasn't enough.

  • One context. A 45K-line spec sweep and a live journal dump do not both fit in it.
  • Serial edits. Seven clusters, one file at a time, forever.
  • Log dumps poison the context — the very thing you need in order to reason.
  • Review monoculture. The author and the reviewer share a mental model, so they share blind spots.
the problem statement → so: partition the work, and the contexts

Act 3/The Protocol 09 / 26
The completion contract

Claude Code has no
deterministic turn-stop hook.

codex, gemini, pi, amp, cursor and ~10 other launchers do. Claude Code does not. So the contract is not an event — it is a line the worker prints. 

TASK-DONE: <role> | <one-line summary>
Always tell a worker the exact TASK-DONE line to print, so you can detect completion. A sentinel you did not specify is a sentinel you cannot grep for.
boss-cmux-team/SKILL.md grep is the API
Act 3/The Protocol 10 / 26
The single most load-bearing gotcha

cmux send submits a separate prompt
on every newline.

A multi-line string is not one prompt. It is N prompts — each half-formed, each dispatched, each racing the next.

If a task is too big for one line, it is too big for one task. Split it.
✗ send types. It does not submit.

Forget send-key enter and your worker sits there with a full prompt buffer, doing nothing, forever. They are two separate calls.

✓ The two-call idiom

cmux send --surface <s> "<one line>"
cmux send-key --surface <s> enter

Act 3/The Protocol 11 / 26
Event loop

Push, don't poll.

Subscribe before the first prompt, then block on the event. Re-reading screens in a loop burns tokens to learn nothing.

# 1. subscribe FIRST — before you prompt anyone
cmux events --name notification.requested \
     --no-heartbeat --no-ack > /tmp/team.ev &

# 2. now dispatch the workers … then block
until grep -q "\"workspace_id\":\"$WS\"" /tmp/team.ev; do
    sleep 1
done

# 3. only now spend tokens reading a screen
cmux read-screen --surface "$SURF" --lines 40
⚠ Match on workspace_id

surface_id is usually null in the event payload. Filter on the workspace, or your until loop never exits.

Subscribe before you prompt

Start the listener after dispatch and you will miss the fast workers' completion entirely — then poll forever for an event that already fired.

The cost model

A poll costs a screenful of tokens every tick. A subscription costs one grep against a file.

Act 6/Case Study C — subagent fan-out 21 / 26
Economics

Model tiering.

Every agent in a fleet does not need to be the smartest model. It needs to be the right one for its job.

TierModelJobToken shape
Orchestrator opus (cc: opus[1m]) Plan, dispatch, verify citations, own the FSM low in · high judgment
Builder opus / codex gpt-5.5 Write code, own exactly one file set medium in · high out
Researcher haiku Read a lot, return a little huge in · tiny out
Reviewer opus, read-only Adversarial pass — try to break it high in · high judgment
Put the cheap model where the tokens are, and the expensive model where the judgment is.

Act 7/Lessons 22 / 26
The honest slide

What broke.

✗ Positional refs renumber.

surface:3 is not a name — it is an index. It shifts as surfaces open and close, and then you are prompting the wrong agent.

→ Anchor everything to a stable window UUID. Resolve positions once, at spawn.
✗ send without send-key.

A worker sitting on a full prompt buffer, doing nothing, forever — and the board says BUILD the whole time, because it never errored.

→ Two calls, always. send types; send-key enter submits.
✗ A multi-line prompt is N prompts.

The rule from slide 10 — learned the hard way, by watching a worker receive four fragments of an instruction and act on the last one.

→ One line, one task. If it doesn't fit, it wasn't one task.
✗ Fork agents overreach.

A fork inherits the whole plan — so it "helpfully" does its neighbours' work too, and races them on shared files.

→ For isolated fan-out use a general-purpose agent with a scoped brief — exactly what Phase A of docs-fleet does.
Notice the shape: every one of these is a silent failure. Nothing crashed. The board just stopped moving — which is why the sentinel and the event subscription exist at all.

Act 7/Lessons 24 / 26
Failures become guardrails

What the fleet taught the repo.

Every failure the fleet hit is now a permanent, documented rule. The scar tissue is the deliverable.

⏳ The silent wait-loop
A VM stuck at cloud-init: running for minutes with no failed unit isn't slow — it's hung. An early install lost the DNS warm-up race (curl: (6) Could not resolve host) and failed without aborting — runcmd is /bin/sh, no set -e — so a later until …; do sleep 5; done now loops forever, silently. tofu apply just prints Still creating…
→ A resolver-ready gate (until getent hosts <host>) + a retry around the installer. Now the standard cloud-init pattern in every cluster.
🧪 The hermetic suite was not hermetic
A gitignored .cross-cluster.auto.tfvars.json is auto-loaded by tofu test — so it silently flips the "off by default" assertions. git status doesn't show it. The tests were reading live fleet state and calling it isolated.
→ just unwire, plus file-level variables {} blocks in every .tftest.hcl to outrank auto-loaded tfvars.
Both are now in CLAUDE.md — read by every future agent on first token. The second one grew into its own skill: triage-patterns. An agent's mistake, written down, becomes every later agent's prior.

Act 8/Close 25 / 26
The whole deck, compressed

The rules that generalize.

01Partition up front. Disjoint files, or one owner per file. Never two agents in one file.
02Phase-lock the shared surfaces. Fan out on research; serialize on authorship.
03Summaries, never dumps. Keep the raw bytes in the cheap agent's context.
04A sentinel beats a poll. TASK-DONE: — and subscribe before you prompt.
05Verify before you fix. Cited evidence, or it didn't happen.
06Live patches don't count. Backport it and rebuild from source, or it isn't real.
